# 2 Phase Locking vs 2 Phase Commit

- Both targets separate goals
1. 2PL provides
   - Isolation (Concurrency Safety). 
   - It Prevents
     - two withdrawals happening simultaneously
     - inconsistent balances
2. 2PC provides
   - Distributed Atomicity
   - It ensures
     - debit and credit both happen OR neither happens

Sample Flow:
```
2PL:
-----
LOCK(A)
LOCK(B)

Updates happen

2PC:
-----
PREPARE
COMMIT

2PL again:
----------
UNLOCK(A)
UNLOCK(B)
```

### PART1 - 2PL (Two Phase Locking)
```
LOCK(A)
LOCK(B)
```
- Prevents other transactions from modifying A or B simultaneously.
- Other transactions trying to access locked rows must wait.

### Part 2 — Local Updates
```
A = A - 100
B = B + 100
```
- Changes are made locally in DB1 and DB2.
- Changes are NOT committed yet.
- Still possible to rollback.

### Part 3 — 2PC (Two Phase Commit)
#### Phase 1 — Prepare/Vote
- Coordinator asks: "Can you commit?"
- Participants: write logs, validate transaction, reply YES/NO

#### Phase 2 — Commit/Abort
- If all vote YES: COMMIT
- Else: ABORT
- After final decision:
```
UNLOCK(A)
UNLOCK(B)
```

> 2PL controls: Who can access data concurrently
> 2PC controls: Whether all databases commit together or rollback together
