# JWT (JSON Web Token)

- Three components - headers, payload, signature
  - Header tells how the JWT token was signed -
    >    {
          "alg": "HS256",
          "typ": "JWT"
          }
  - Payload contains claims about the user/token. Example Claims may contains the authorization the user has to access different resources.
    > The payload is Base64URL encoded, not encrypted. Anyone who has the JWT can decode it and read the contents, so don't put passwords or sensitive information in it.
  - Signature protects the header and payload from being changed silently 
    > sign(
      base64url(header) + "." + base64url(payload),
      signing_key
     ) 
     signing_key can be secret_key(for HMAC) or private_key(for RSA)

- **FINAL JWT = Base64(Header).Base64(Payload).Base64(Signature)**

- Secure way of transmitting data between parties using JSON object
- THis infomration can be verified because it is digitally signed by RSA(public/private key) etc.

- Advantages:
  - Compact in size. Can be sent in Header and transmits fast due to its size.
  - Payload contains all the information about user. So it is **Stateless**
  - Can be signed using Symmetric(HMAC) or Asymmetric(RSA)
  - Built in expiry mechanism
  - Custom Claim(additionla data) can be added in the JWT
