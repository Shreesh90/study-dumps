# Thundering Herd Effect

> https://www.youtube.com/watch?v=1aamH7sA8FY&list=PL6W8uoQQ2c63W58rpNFDwdrBnq5G3EfT7&index=31


- When suddennly millions of request comes to a service. Example- ticket booking when sale goes live.
- Issues:
  - We have load balancer in the front to distribute the requests to different application servers.
  - Each server might be working in its full thread capacity and the request queue for each server might be full as well
  - Number of instance of servers might have been increased from Autoscaling but even those new servers might be working in full capacity with full queue.
  - When systems work in full capacity, it tends to increase the latency of each requests because systems need extra space to cater to these request
  - Increased latency can lead to requests timeouts. And each of these requests will retry 
  - But even in case of retry millions of requests might try to retry at the same time, we need to solve this. 

- Solution
  - Exponentioal Backoff
    - Formula: ```base * 2^n``` (n - number of failures)
    - We delay the retry request by above value before it tries again
    - But again all the retry requests might retry at the same time, again landing us in problem
  - Exponentioal Backoff + Jitter
    - Formula: ```min(max wait time, Random(base*2^n))``` (n - number of failures)
    - Above value ensures all requests dont retry at the same time 
  - Rate Limiter can also be used
  - So a mix of Rate Limiter and Exponentioal Backoff + Jitter can be used as a solution
